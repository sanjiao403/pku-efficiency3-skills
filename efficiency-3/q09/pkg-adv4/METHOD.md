# METHOD — 方法选择与理由（不是操作手册，操作见 SKILL.md）

本文件回答「为什么这样做」，尤其是**哪些做法是被实测推翻后改掉的**。数字都来自
`benchmark.json`、`tests/selftest-report.json`、`tests/lead-audit-report.json`（可复跑）。

## 1 核心方法：抽取而非生成

页面要点只取材料里的**整句原文**，每条带 `{source, page, block_id, quote}`。
理由是题面点名的失败模式——「把摘要整段塞进文本框」「关键数字抄错或按印象取整」：
只要页面文字是原文整句，数字抄错在构造上不可能发生，而机检 C13 只需核对数字是否出现在被引句里。
代价：读起来不如改写稿顺，所以允许 agent 在 `deck_plan.json` 里改写要点，但改写必须带
`quote`（原句），`deck.py` 会把原句写成 `改写自原句：…` 落到备注，C12 逐字核验它。
`result.json.claim_support` 会如实写明「entailment 未机检」，不冒充语义审计。

## 2 自证必须读**交付物**，不能读内存里的页计划

父臂（`pkg-min2`）的引文/来源检查读的是运行期 `deck_spec`，而页面文字就是从同一份 spec 来的——
等于让计划给自己作证。实测：把第 4 页正文换成编造句、只保留原锚点，父臂与 `pkg-min4`
都仍然 `checks_passed=true`（见 `tests/lead-audit-report.json` 的 P2/P6 行）。
本包改成**从交付的 pptx 备注里解析锚点**（`verify.py: page_anchors`），再回材料核验：
同样的篡改现在会让 C12 变红。

## 3 数字保真必须**按页**限定

把「只在全篇台账里能找到」当通过条件，会出现「数字在论文里存在、但被搬到了无关的那一页」的假绿
（实测 P3：父臂全绿）。本包要求数字出现在**该页自己的**引文或它引用的材料块/页里，否则判
`wrong-page-scope`；讲解路线页按整篇台账核对。可用 `number_scope: "material"` 显式降级（并在报告里留痕）。

## 4 证据边界：工单永远不是证据

实测（哨兵法）：真实 `/input` 布局下 `task.md` 与 `case.json` 同在，父臂把 **`task.md` 当成引文语料**
（`sources[] = ["task.md"]`，哨兵进入 `source.json`）。因此本包先用
`evidence_ok()`（扩展名白名单 + 文件名黑名单 + 工单特征词嗅探）过滤候选，
再用 `usable_spec/usable_ops/usable_pptx` 校验页计划/编辑指令/模板的形状——
顺带修掉「`/input` 里有个示例 JSON 就被当成页计划并让整次运行崩溃」这个 P0。
`verify.py: corpus_verdict()` 是第二道防线：语料文件不像研究材料时 C12/C13 直接失败。

## 5 模板不变量：选对基线，别造基线

编辑既有 deck 时，父臂拿「本次自建的中性母版」当对照，于是每一次正常编辑都被判
`template_preserved=false`、`status=partial`（实测本地案例 C：8 页编辑成功却判 partial）。
本包把基线换成交付里**真实被测的那份文件**：有模板用模板，编辑用被编辑的既有稿，
只在两者都没有时才用自建母版，并在 `checks.C10.detail.baseline_role` 写明是哪一种。
起始 deck 自带的引用问题记为 `inherited_from_input_deck`，不算这次运行的责任。

## 6 导出件要**字节级重测**，不能信渲染器自述

`C14` 重新打开导出的 PDF 测量：页数、页面尺寸（±2 pt）、逐页文字存活率（≥0.82）、实际字体列表。
这把「导出后字体被替换／文字被裁」从自述变成可失败项（本地实测三案例存活率均 1.0，
字体分别落到 `MicrosoftYaHei/Calibri` 与 `SimSun/TimesNewRoman`，可复核）。
`C15` 检查每个图片形状是否含真实图片部件（≥2 KB、≥16×16 px）并渲染出自己的 PNG——
「图表位置放一张占位图」因此可以被机检抓到。

## 7 检查为什么可信：负向对照

一份只有绿灯的自检报告证明不了什么。`tests/selftest.py` 的 T7–T13 与
`tests/lead-audit-report.json` 的覆盖矩阵对每个 id 做一次定向篡改，要求它变红；
未被篡改的表格/图片 deck 仍须 0 失败（矩阵里的 `C01-aux` 行），防止把检查写成常红。
父臂对照：`pkg-min2` 只覆盖 C02，`pkg-min4` 覆盖 C01–C10 但 C11/C12/C13 全绿。

### 7.1 独立交叉终检（QA-round-20261124）抓到的四类错，以及为什么它们值得单独写一节

- **契约字段被遍历变量覆盖**（`case_id` 恒为 `"C07"`）：这是"看起来完全正常的报告"里最危险的一类，
  因为 case_id 是平台绑定结果的键。现在 `deck.py` 里契约变量与循环变量分离，`result.json`
  另带 `contract_selfcheck.case_id_matches_input`，C16 会把 `case_id` 与输入逐字比对（T11 负向对照）。
- **机检的对照语料是自己写的**：`sources[]`、锚点来源名以前没人审。现在 C16 审 `sources[]`、
  C11 审每条锚点的**来源名**（`task.md`/`case.json`/示例即使在材料里能解析也判红，T13）。
- **只数文件不读像素**：C15 以前只数 PNG 个数，把整页换成纯白也能全绿。现在每页 PNG 都要读像素
  （96×96 采样：可读、非空白、不重复、纵横比与画布一致，T9/T8）。
- **空壳页与契约不一致**：内容页没有正文也能"13/13 全绿 + status=success"；`notes` 契约字段写的是
  计划而不是交付物。现在 C08 要求内容页有正文（除非声明 `[备份]`），`notes` 从 deck.pptx 读回，
  C16 逐页比对（T10/T12）。

### 7.2 顺带抓到的生产级缺陷

`render()` 以前会复用 `preview/deck.pdf`：同一输出目录重跑时，上一轮的 PDF 会被当成本轮渲染，
C14 因此量到 0.35 的文字存活率（新旧 deck 内容不同）。现在渲染前先删旧预览。
另外"一页塞不下"以前会缩到 12 pt 后溢出裁切（导出后文字丢失），现在改为从末尾丢要点并记
`build_report.dropped_for_fit`——宁可少一条要点，不让页面上出现被裁掉的句子。

## 8 明确不做的事

- 不反演论文曲线数据、不合成占位图（宁缺一张图，不造一张图）；
- 不判断改写要点是否被原句**语义**支撑（机检做不到，只在 `claim_support` 里声明）；
- 不在无渲染器时伪造 PNG（`render_status=unavailable` + C14/C15 `n/a`）；
- 不把示例/工单/模板写进证据索引，也不把三个固定案例的正式答案写进包。

## 9 预算与中断

单案例 6–20 s（解析 2–6 s、生成 <1 s、渲染 ≈6 s、机检 <1 s），远低于 900 s / 64 请求。
进入渲染前先写一份 `_partial: true` 的诚实 `result.json`：即使中途被中断，平台拿到的仍是
有效且不撒谎的文件（父臂 `pkg-min4` 的这一做法被保留并修掉了「契约字段被空串覆盖」的缺陷）。
