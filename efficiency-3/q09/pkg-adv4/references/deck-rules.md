# deck-rules — 版式、证据与机检规则（adv2 版）

本文件是 `scripts/deck.py` 与 `scripts/verify.py` 的**共同口径**。规则冲突时以代码为准，本文件描述代码。

## 1 页面角色与页数

```
封面(1) → 讲解路线(1) → 问题 → 方法 → 结果×2 → 限制 → 结论   （页数不足时补 结果/备用页）
```

一页一个**主张**（claim，写在演讲备注的 `[主张]` 行）；主张必须能被材料里的一句话锚定。
页数由 `case.json` 的 `slide_count`/`num_slides`/`max_slides` 决定（顶层或一层嵌套均可）；
时长 `duration_min`/`minutes` 只影响讲稿节奏。

材料整句池按**轮转**分配到各内容页（先保证每个角色都拿到一句，再考虑给同一页加第二句），
所以不会出现"前面几页塞满、结论页空白"。池子不够时，剩下的页写成**声明式备用页**：
标题用"备用页"、备注以 `[备份]` 开头、不出任何主张，并在 `result.json.uncertainty` 与
`deliverable.declared_backup_pages` 里点名。

## 2 版式硬约束（机检口径）

| id | 项 | 约束 |
|---|---|---|
| C01/C02 | 页数 | = 案例指令 / ≤ 上限；case.json 没给时记 `n/a` 并说明 |
| C03 | 出血 | 所有形状在幻灯片内（含表格框、图片框） |
| C04 | 溢出 | 字符预算估算不超槽位（估算口径见 §5） |
| C05 | 重叠 | 两个正文形状交叠 > 小框面积 12% 即失败 |
| C06 | 表格 | 表体宽/高不得超过自身框与画布（产物无表格时 `n/a` + 原因） |
| C07 | 图片 | 放置纵横比与图片原始纵横比误差 ≤2% |
| C08 | 标题/备注/正文 | 每页要有标题文本（标题文本框也算）、非空演讲备注与**非空正文**；正文为空只有在备注里声明 `[备份]` 时才被接受（并点名） |
| C09 | 字号 | 正文 ≥12 pt（图注/页脚/页码/标题豁免） |
| C10 | 母版不变 | 幻灯片尺寸 + 主题字体 + 各版式占位符几何的**设计指纹**与基线一致 |
| C11 | 锚点 | 每页内容要有可解析的 `[来源]` 锚点（语法见 §3），且**来源名必须是研究材料**：`task.md`/`case.json`/示例即使在材料里能解析也判红 |
| C12 | 引文真实 | 锚点句必须逐字出现在材料里；改写句必须带 `改写自原句：` 且该句逐字真实 |
| C13 | 数字保真 | 页面上每个 ≥2 位数字必须出现在**本页**引文或本页所引材料块/页里 |
| C14 | 导出重测 | PDF 页数=幻灯片数、页面尺寸=幻灯片尺寸(±2pt)、逐页文字存活率 ≥0.82、记录实际字体；**渲染前必须删除上一轮遗留的预览**，读到旧 PDF 即判红 |
| C15 | 无占位图 | 每个图片形状必须含真实图片部件（≥2 KB、≥16×16 px）；每页 PNG 必须**读像素**：可读、非空白（96×96 采样 ≥3 色且主色 <99.5%）、不重复、纵横比与画布一致 |
| C16 | 契约=交付物 | `case_id` 必须与输入一致；`sources[]` 只能是研究材料；`notes[]` 必须等于产物里实有的备注；`deliverable.slides` / `outputs[].bytes` 必须与产物一致 |

`n/a` 一律带原因、**绝不算通过**，并写进 `result.json.checks.summary.not_applicable`。

## 3 证据语法（演讲备注，C11/C12 靠它解析）

```
[主张] <这一页的主张>
- <句>  [来源 <材料文件> p.<页|-> <块id>]
  改写自原句：<材料里的原文句>        ← 仅当 <句> 不是原文整句时出现（C12 会核验它）
- <导航项>  [路线]                    ← 讲解路线页，不声称材料证据
[讲稿] <讲稿>
[备份] <声明式备用页：本页不作任何主张>   ← 无正文的页必须带这一行
```

- 锚点**必须可解析且来源合法**：块 id 不存在且页面也对不上 → C11 失败；锚点行格式坏掉
  （多个 `[来源` 挤在一行）→ C11 失败并原样报出该行；来源写成 `task.md`/`case.json`/示例 →
  C11 失败（"拿工单当出处"在交付物层必须可检）。
- 起始 deck 自带的锚点问题记为 `inherited_from_input_deck`，不算本次运行的责任。
- 页脚：`来源 <材料名> · p.<页码,…>   <当前>/<总页数>`。
- 讲稿缺失时 `deck.py` 会用角色模板生成一段**只引用本页原句**的讲稿骨架
  （`ROLE_SCRIPT` + `auto_script()`），不会编造科学内容。

## 4 证据边界（决定「引文索引里能放什么」）

**只有研究材料能当引文语料**（`scripts/deck.py: evidence_ok()`）：

1. 扩展名白名单：`.pdf/.md/.markdown/.txt/.text`（`.json/.pptx/.png/...` 一律不是证据）；
2. **文件名规则用锚定匹配，不用子串**（v2 修订）：
   - 精确拒绝的 basename：`task.md`、`task.txt`、`task.json`、`case.json`、`case.md`、
     `case.txt`、`README.*`、`rubric.*`、`SKILL.md`、`METHOD.md`、`NOTES.md`、`benchmark.*`、
     `deck-rules.md`、`prompt.md`、`instructions.md`；
   - 明确后缀拒绝：`*.example.json/.md/.txt`、`*.template.json/.md/.txt`、`*.schema.json/.md`，
     以及 `template-spec*` / `template-plan*` / `template-deck*`；
   - **名字里只是碰巧含 `case`/`task` 的真论文必须放行**（`case-study-routing.md`、
     `case_report.md`、`task_notes.md` → 当材料读取）。官方案例的材料文件名未知，
     把真材料判成工单会造成 `slides=0 / failed`，比漏拦严重得多。
3. **内容嗅探（拦真工单的手段，且只认「合同独占词」）**：
   在文件前 20,000 字符里数**互异**的合同独占词——`output_contract`、`runtime contract`、
   `submission_contract`、`deliverable_contract`、`提交材料`、`收到材料`、`提交目录`、`交付要求`、
   `交付标准`、`提交要求`、`提交清单`；**≥2 个**即拒；或出现**无歧义提交警告句**
   （`do not submit prepared answers` / `不得提交预制答案`）即拒。
   **评分类词汇只记录、永不作判据**，分两档：
   - corroborating：`评分维度`、`评分点`、`评分细则`、`prepared answer`、`预置答案`、`case_id`、`task_id`；
   - weak：`grader`、`rubric`、`whiteboard`、`llm-as-a-judge`、`judge model`。
   理由：中文评测论文描述自己的标注方案（"评分维度包括…；每个评分点 1–5 分；评分细则见附录 A"）
   与检索问答论文里的 `prepared answers` 都是**真论文**，误拒会让该案例 `slides=0/failed`，
   比漏拦贵得多。代价如实记录：一份只提"提交材料"一项、没有其它合同独占词的工单会漏拦。
   每个候选的嗅探结论（三档标记名、决定性短语、判定）写进
   `result.json.stages[discover].evidence_sniff`。

被拒的候选写进 `result.json.stages[discover].refused_as_evidence`（含原因）。
**页计划/编辑指令/模板同样过分形状校验**（`usable_spec/usable_ops/usable_pptx`）：
`slides[]` 不是对象列表、`ops` 不带 `op` 键、`.pptx` 打不开 → 拒收并记原因，绝不静默采用。
`verify.py: corpus_verdict()` 是同一规则的**第二道防线**：语料文件若不像研究材料，C12/C13 直接失败；
`C11 locator_ok()` 是第三道：交付物里每条锚点的**来源名**也要过同一套规则。

## 5 估算模型

CJK 字宽 = 字号×1.0，拉丁 ×0.55，空格 ×0.30，行高 ×1.25（±8%）。
生成时按 `need = Σ(1 + len(text)//22) × 22pt` 与槽位高度比较：
放得下就用 17 pt，放不下线性降到 12 pt 下限；**到 12 pt 还放不下就从末尾丢要点**
（记 `build_report.dropped_for_fit`），绝不低于 12 pt、绝不靠溢出裁切凑页数。

## 6 模板、编辑与导出

- 模板只被**读**：`probe()` 取版式名、占位符几何、安全区；内容只进版式槽位（槽位缺失时用文本框）；
- 无模板 → python-pptx 默认母版 + 16:9 画布，warning 里报明；
- 编辑只作用于被点名的页；**设计指纹** = 幻灯片尺寸 + 主题 `typeface` 集合 + 每个版式的
  `{占位符 idx, x, y, w, h}`；前后不一致即 `template_preserved=false`，并给差异清单；
- 编辑模式下 C10 的对照基线是**被编辑的那份既有稿**；生成模式下是给定模板（无模板时是本次自建母版）；
- 每次编辑留 `versions/<deck>-v0-original.pptx` 与 `-v1-edited.pptx`；
- 导出件（PDF/PNG）是**运行期产物**，可以且应当是二进制（Runtime contract: runtime artifacts may be
  binary），但**包内资源树零二进制**；C14 对导出件做字节级重测而不是相信渲染器自述；
  渲染前先删旧预览，避免"上一轮的 PDF 冒充本次渲染"。

## 7 降级原则

1. 能做的先做、先落盘（进入渲染前就写一份 `_partial: true` 的诚实 `result.json`）；
2. 不能做的写进 `uncertainty`/`limitations`，并让 `status` 变 `partial`；
3. 不编造：不生成占位图、不重打数字、不伪造渲染件；
4. 渲染器缺失时**不产出 PNG**（没有「几何预览冒充渲染」这条路），C14/C15 记 `n/a` + 原因；
5. 契约字段一律从产物读回（`notes_origin` 会标注），C16 逐项比对，任何"计划里是这样"的字段都会判红。

## 8 已知边界（必须让评审看到）

- **C12 只证明引文真实，不证明语义支撑**：它无法判断「这条改写要点是否真的由原句支撑」。
  `result.json.claim_support` 会给出改写条数与「零共享词」条数，并明写 entailment 未机检。
- C13 只看数字，不看叙述；不含数字的编造结论躲得过机检（人读仍能发现，因为每页都给了原句）。
- C04 是字符宽度估算，不是像素测量；渲染件 C14 才是像素级证据（文字存活率 + 页面尺寸）。
- C15 的"空白"判定是 96×96 采样 + 主色占比，不判"内容是否切题"；一张纯色但有文字的图能通过。
- 图：本包**不裁剪、不重绘、不合成**图；材料里的图无法引用时只保留文字与页码，在
  `uncertainty`/`limitations` 里说明（宁可少一张图，不造假图）。
